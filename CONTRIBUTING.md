# Contributing

Thanks for helping improve SkillChain.

## Before changing code

1. Read the [README](README.md), [architecture](docs/ARCHITECTURE.md), [roadmap](docs/ROADMAP.md), and [security policy](SECURITY.md).
2. Open an issue for significant feature work so scope and acceptance criteria are clear.
3. Use a focused branch such as `feature/skill-search` or `fix/navigation-state`.
4. Keep changes small enough to review and preserve the existing prototype unless a replacement is explicitly planned.

## Pull request checklist

- [ ] Explain the user problem and intended behaviour.
- [ ] Describe files and architecture affected.
- [ ] Include tests or precise manual verification steps.
- [ ] Check keyboard navigation, responsive layout, and accessible labels for UI changes.
- [ ] Identify privacy, security, and data-migration impact.
- [ ] Do not add real personal data, secrets, private keys, or fabricated success metrics.
- [ ] Update documentation and note any known limitations.

CI checks are useful safeguards, not a substitute for runtime, integration, accessibility, or security testing.
